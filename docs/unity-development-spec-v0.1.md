作成日：2026年10月30日  
研究テーマ：N1分析を用いたペルソナ特化型リズムゲームの制作  
対象：Rhythm Football（卒業研究・検証用ゲーム）

> この文書は2026年10月19日の第1回N1試遊評価を受けた**実装計画案**。N1評価で確定した事項と、制作者がこれから試す仮説を区別する。現時点でUnity版の各機能が完成したことは意味しない。

## 1. 目的と制作方針

- 11月はUnityによる制作に集中し、**11月15日（日）までに一通り遊べるUnity版の基本機能を完成**させ、遅くとも**11月22日（日）までにAndroid実機確認と主要な不具合修正**を終えることを目指す。ただし進捗に応じてスコープを調整する。
- 最終成果物は**Unity / C#によるAndroid向け横画面ゲーム**。Web版（HTML/JavaScript）はN1評価と仕様検証に使うMVPであり、完成版はUnityで改めて実装する。
- 開発の根拠は「N1の発言・観察 → 解釈 → 仕様の仮説 → 試作 → 再評価 → 改善」として記録する。
- 3D外観や演出は魅力を高める手段であり、**最初はUnity標準のCube・Sphere・Capsuleなどの仮素材**で動く仕組みを作る。後で合法的な素材に交換する。
- 音楽ゲームという形式は暫定。音なしで遊ぶ対象者の特徴を踏まえ、結果によって形式を見直す可能性を残す。

## 3. Unity版のゲームの基本ルール（初期仮説）

- 横持ち。開始前は画面中央に**3 → 2 → 1 → START!**のカウントダウンを表示し、START!で60秒の計測を開始する。音ありでは短いカウント音、音なしでは文字表示のみとし、リトライ時も同様に実行する。
- 1プレイ60秒。
- 足のボールには左側のKICK、頭のボールには右側のHEADで対応する。
- ボールが画面の判定リング（足元/プレイヤー付近）に達するタイミングで入力。
- PERFECT＝100点、GOOD＝50点、MISS＝失点（現Web版ルールを仮採用）。各判定はエフェクト・効果音・シュート軌道にも反映させる。
- 画面にスコア、残り時間、現在の操作モード、音なしでも読めるタイミング指示を表示し、飛来するボールと重ならない配置にする。
- 音あり／音なしを選べる。**本格的な楽曲は未選定・未実装**。まずオリジナルの簡易ビートで同期を検証し、第三者の音源を無断で組み込まない。

## 5. シーンとスクリプト設計（案）

**Scene**：Main（タイトル、ゲーム、結果をパネル切替）から始める。

**Hierarchyの例**
```
Main
├── Directional Light
├── Main Camera
├── Stadium
│   ├── Field (Plane)
│   ├── Goal (Cubes)
│   ├── Player (Capsule)
│   └── Goalkeeper (Capsule)
├── BallSpawner
├── HitTarget
└── Canvas
    ├── TitlePanel
    ├── HUD (Score, Timer, Mode)
    ├── TouchButtons (Kick, Head)
    └── ResultPanel
```

**C#コンポーネント案**
- `GameManager`：開始、タイマー、終了、リトライ。
- `RhythmClock`：BPMと判定時刻の基準。音ありのときは`AudioSettings.dspTime`等を利用した時間同期を検討する。
- `BallSpawner` / `BallMover`：種類の決定、出現、リングへの移動。
- `HitJudge`：ボール種類と入力時刻からPERFECT/GOOD/MISSを返す。
- `InputManager`：画面左右タップとEditor用キーボードを同じ入力に変換。
- `ScoreManager`：スコア・判定数。
- `ShotEffectController`：判定に応じた飛球、ゴール演出。
- `UIController`：HUD、説明、結果表示。

**判定同期で注意する点**：ボールの見た目がリングに到達する時点と判定中心を一致させる。スマホのfps差で結果が変わらないようフレーム数ではなく時間で処理。音声再生遅延は実機で検証する。

## 6. 11月の実装計画（教授の助言を受けて前倒し）

**完成の定義（第一目標：11/15）**：Unity Editor上で、ゲーム開始→3/2/1/START→60秒ゲームプレイ→ボール飛来→KICK/HEAD操作→PERFECT/GOOD/MISS判定→スコア→結果表示→再プレイを一通り実行できること。フィールドや選手は標準Primitiveの仮モデルでよい。Android実機ビルドは11/15までを目標に試み、問題があれば11/22までに解消する。

| 期間 | 最優先目標 | 達成確認 |
| --- | --- | --- |
| 11/2〜11/8 | Unityプロジェクト・仮3Dスタジアム・ボール移動・左右入力・時間判定までを一気に実装 | Editor上で操作と判定ができ、ゲームの骨格が動く |
| 11/9〜11/15 | 3→2→1カウント、60秒タイマー、スコア、結果画面、リトライ、音あり/なし、Androidビルド試行 | 60秒間、一通りプレイできる基本完成版 |
| 11/16〜11/22 | Android実機動作確認、重大な不具合修正、視認性と入力タイミングの調整 | Android端末で開始から結果まで動作する状態を目標 |
| 11/23以降 | N1再評価、改善効果の分析、卒論と発表資料の準備 | 研究結果を文章化 |

**スコープを絞る**：ランキング（自己ベスト含む）、高度な3Dモデル・観客・複雑なシュートアニメーション・本格的な音楽制作は、11/15までの必須機能から外す。最初はUnity標準のPrimitiveと単純な効果音で実装し、N1アンケートで重要だった操作性・視認性・判定を優先する。

**作業開始前の確認**：Unity 6.4（6000.4.2f1）を予定。Universal 3D（URP）プロジェクトの有無、Android Build Support（SDK/NDK/OpenJDK）が実際に導入されているか、テスト用Android端末を確認する。環境準備の記録と、Editor上での実装完了は区別する。
