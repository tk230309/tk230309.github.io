# Unity版ゲーム制作仕様書 v0.1

作成日：2026年10月30日  
研究テーマ：N1分析を用いたペルソナ特化型リズムゲームの制作  
対象：Rhythm Football（卒業研究・検証用ゲーム）

> この文書は2026年10月19日の第1回N1試遊評価を受けた**実装計画案**。N1評価で確定した事項と、制作者がこれから試す仮説を区別する。現時点でUnity版の各機能が完成したことは意味しない。

## 1. 目的と制作方針

- 11月はUnityによる制作に集中し、11月末には**操作開始から結果画面まで一通り遊べる版**を目指す。ただし進捗に応じてスコープを調整する。
- 最終成果物は**Unity / C#によるAndroid向け横画面ゲーム**。Web版（HTML/JavaScript）はN1評価と仕様検証に使うMVPであり、完成版はUnityで改めて実装する。
- 開発の根拠は「N1の発言・観察 → 解釈 → 仕様の仮説 → 試作 → 再評価 → 改善」として記録する。
- 3D外観や演出は魅力を高める手段であり、**最初はUnity標準のCube・Sphere・Capsuleなどの仮素材**で動く仕組みを作る。後で合法的な素材に交換する。
- 音楽ゲームという形式は暫定。音なしで遊ぶ対象者の特徴を踏まえ、結果によって形式を見直す可能性を残す。

## 3. Unity版のゲームの基本ルール（初期仮説）

- 横持ち、1プレイ60秒。
- 足のボールには左側のKICK、頭のボールには右側のHEADで対応する。
- ボールが画面の判定リング（足元/プレイヤー付近）に達するタイミングで入力。
- PERFECT＝100点、GOOD＝50点、MISS＝失点（現Web版ルールを仮採用）。各判定はエフェクト・効果音・シュート軌道にも反映させる。
- 画面にスコア、残り時間、現在の操作モード、音なしでも読めるタイミング指示を表示し、飛来するボールと重ならない配置にする。
- 音あり／音なしを選べる。**本格的な楽曲は未選定・未実装**。まずオリジナルの簡易ビートで同期を検証し、第三者の音源を無断で組み込まない。

## 5. シーンとスクリプト設計（案）

**Scene**：Main（タイトル、ゲーム、結果をパネル切替）から始める。

**Hierarchyの例**
```
Main
├── Directional Light
├── Main Camera
├── Stadium
│   ├── Field (Plane)
│   ├── Goal (Cubes)
│   ├── Player (Capsule)
│   └── Goalkeeper (Capsule)
├── BallSpawner
├── HitTarget
└── Canvas
    ├── TitlePanel
    ├── HUD (Score, Timer, Mode)
    ├── TouchButtons (Kick, Head)
    └── ResultPanel
```

**C#コンポーネント案**
- `GameManager`：開始、タイマー、終了、リトライ。
- `RhythmClock`：BPMと判定時刻の基準。音ありのときは`AudioSettings.dspTime`等を利用した時間同期を検討する。
- `BallSpawner` / `BallMover`：種類の決定、出現、リングへの移動。
- `HitJudge`：ボール種類と入力時刻からPERFECT/GOOD/MISSを返す。
- `InputManager`：画面左右タップとEditor用キーボードを同じ入力に変換。
- `ScoreManager`：スコア・判定数。
- `ShotEffectController`：判定に応じた飛球、ゴール演出。
- `UIController`：HUD、説明、結果表示。

**判定同期で注意する点**：ボールの見た目がリングに到達する時点と判定中心を一致させる。スマホのfps差で結果が変わらないようフレーム数ではなく時間で処理。音声再生遅延は実機で検証する。
